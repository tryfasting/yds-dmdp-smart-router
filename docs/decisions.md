# Decisions & Audit Findings

## 1. 문제 정의와 타깃

- **서비스**: 한국어 문장 교정(Sentencify). 사용자가 강도(WEAK / MODERATE / STRONG)와 분야를 고르면 LLM이 교정합니다.
- **라우팅 목표**: 어려운 요청만 상위 모델(heavy)로, 나머지는 경량 모델(light)로 보내 비용을 줄입니다.
- **라벨**: Gemini가 원문과 교정문을 비교해 교정 난이도를 1–5점으로 채점했고, score ≥ 4를 Hard(1)로 정했습니다. 채점 기준은 "구조·톤 변화가 크면 Hard"로, **교정 결과가 얼마나 바뀌었는가**를 봅니다.
- **초기 ML(RF/LightGBM/CatBoost)**: 이벤트 로그에서 `run_`으로 시작하지 않는 이벤트를 1로 둔 이벤트 분류였습니다. 요청별 수락 확률 모델이 아니며, 라우터와는 다른 문제입니다. 중요도는 인과 효과가 아닙니다.

## 3. 분할·체크포인트·임계값 (제출 V8)

- klue/roberta-base, 입력 형식 `[INTENSITY] [FIELD] sentence`, max_length 128, class-weighted loss를 썼습니다.
- label 층화 85:15 분할(seed 42)이고, **eval_dataset = test**입니다. best F1 기준 checkpoint-205(epoch 1, eval F1 .7837)를 선택했습니다.
- 임계값 0.25도 같은 test 셋의 F1으로 골랐습니다.
- 따라서 test 지표는 **모델 선택에 쓰인 분할의 결과**이며 낙관 편향이 있습니다. 별도 hold-out은 없습니다.

## 4. 감사 결과 A — 분류기는 강도 규칙과 사실상 같다

`smartrouter evaluate`, 저장 예측 1156행 기준 결과입니다.

| | TP | FP | TN | FN | Precision | Recall | F1 | heavy 배정률 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| RoBERTa @0.25 | 467 | 183 | 438 | 68 | .718 | .873 | .788 | 56.2% |
| 규칙: STRONG → heavy | 465 | 181 | 440 | 70 | .720 | .869 | .788 | 55.9% |

- 두 결정의 일치율은 **99.65%**입니다.
- 강도별 확률 범위(WEAK .03–.08 / MODERATE .10–.28 / STRONG .40–.83)가 겹치지 않습니다.
- 같은 강도 안에서의 판별력은 AUC STRONG .618, MODERATE .667로 약합니다(전체 AUC .843의 대부분이 강도 태그에서 나옴).
- **원인**: 라벨(교정 변화 크기 채점)과 v2 강도 태그(교정 변화 비율 역산)가 같은 교정 결과에서 나왔습니다. 모델은 문장 난이도보다 이 태그를 학습했습니다(지름길 학습).
- **실사용 해석**: 서비스에서는 사용자가 강도를 직접 고르므로 태그 자체는 요청 시점에 쓸 수 있는 정보입니다. 다만 학습 데이터의 태그는 결과에서 역산한 값이어서, 실제 사용자가 고른 강도와 같은 분포라는 보장이 없습니다.

## 6. 감사 결과 C — 생성·Judge 평가

`smartrouter judge-report`, 100건 기준 결과입니다.

| 시나리오 | 평균 점수 | 추정 비용 (USD) |
|---|---:|---:|
| A light only (gpt-5-nano) | 4.280 | 0.00120 |
| B heavy only (gpt-5-mini) | 4.365 | 0.00592 |
| C router @0.25 | 4.295 | 0.00375 |

- 과거 보고의 산술(C는 B 대비 비용 36.6% 절감, 점수 98.4%)은 재현됩니다.
- 그러나 쌍체 bootstrap 95% CI는 C−A +0.015 [−0.22, +0.245], B−A +0.085 [−0.15, +0.305]로, **모든 차이의 구간이 0을 포함합니다.** 100건으로는 시나리오 간 품질 차이를 입증하지 못합니다.
- A만 써도 B 점수의 98.1%가 나옵니다. "98% 품질 유지"는 라우터 고유의 효과가 아닙니다.
- 비용은 `글자수 / 2.5` 토큰 추정에 단가를 곱한 값입니다. 실제 usage가 아니고 reasoning 토큰·Judge 비용이 빠져 있습니다.
- 100건 중 heavy 라우팅 55건은 STRONG 55건과 같습니다(일치율 100%). 같은 절감은 강도 규칙으로도 얻을 수 있습니다.

## 7. 수정 정책

- 원본 병합 코드의 dtype 기반 `drop_duplicates(subset=hashable_cols[:10])`는 pandas 버전에 따라 선택 키가 달라집니다(pandas 3에서 784행 제거). 이 레포는 이를 쓰지 않고, `validate="one_to_one"` / `"many_to_one"`으로 카디널리티를 검사합니다.
- `recent_execution_date`는 원 코드에서 두 번 변환되어 v3에서 전부 결측입니다. v3는 과거 산출물로 해시만 검증하고, 조용히 교체하지 않습니다.
- 라우터는 모델을 불러오지 못하면 오류를 냅니다. 학습되지 않은 헤드나 고정 확률로 대체하지 않습니다.

## 8. 다음 과제

- 강도 태그 이외의 문장 신호 측정: 원문 기준 그룹 분할과 train/val/test 분리 후, 강도만 / 문장만 / 강도+문장을 비교하는 CPU 진단 실험(별도 승인 후 실행).
- 신호가 확인되면 클라우드 GPU에서 더 큰 한국어 모델로 확장합니다.
- 라벨 재정의: 교정 결과의 변화량 대신 요청 시점에 관측 가능한 품질 기준(예: 경량 모델 결과가 Judge 기준을 통과하는지)을 검토합니다.
